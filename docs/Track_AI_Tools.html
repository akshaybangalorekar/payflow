Using AI as an engineer, not a tourist

The role division

AI is the fastest junior developer you have ever met: tireless, well-read, confident — and sometimes confidently wrong. You are the senior who reviews its work. That division is exactly the AI-resistance argument you wanted on your resume: the typist gets replaced; the verifier does not. Every habit below exists to keep you on the verifying side of the desk.

Prompting with context

Bad: "my build fails help"

Good: "Spring Boot 4.1, Java 25. mvn spring-boot:run fails with: [paste the FIRST error lines, not the debris]. My pom has spring-boot-starter-webmvc. I already tried X. What causes this?"

The formula: versions + first error + what you tried. Context in, accuracy out. AI tools don't read minds; they read prompts.

Where AI shines

Boilerplate (DTOs, mappers, config), test cases for existing code, explaining unfamiliar stacks ("what does this annotation do"), migration scripts, regex, and rubber-ducking design decisions. These are all high-volume, low-risk drafts that you can verify quickly.

Where it lies

You already have a scar from this: most tutorials on the internet still say spring-boot-starter-web, but Spring Boot 4 renamed it to webmvc — AI trained on old data hands you a broken pom with total confidence. Same failure modes: invented APIs that don't exist, outdated versions, and security holes (it will happily generate endpoints that trust client input). The check is always the same: try it, read the first error, verify against current docs. That verification loop is a skill you build by doing what you're doing in PayFlow — hands on real code, not accepting generated output on faith.

House rules while you're in coaching phases 1–3

Use AI to explain, not to write your exercises. Asking "why does @Transactional go on the service, not the controller?" grows you; pasting the flaw-fix assignment into a chat and copying the answer grows nothing. When you reach Phase 3, the rule relaxes — velocity tools for a developer who has already built the verification instincts. And one rule that never relaxes: secrets never go into a chat window. Same law as .env and git history.
