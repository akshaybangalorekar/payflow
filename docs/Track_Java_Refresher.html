Java 8 → 25: what you missed

The language grew up while you were away. Here is the 20% you will use daily in PayFlow.

The timeline

Java 8 (2014) brought lambdas, streams, and Optional — the biggest shift in the language's history. 11, 17, 21 (LTS) added modules, records, sealed classes, pattern matching, and virtual threads. Java 25 (LTS, 2025) is your current LTS. PayFlow code is written in modern idiom, so this page is your bridge from the Java you remember.

1 · Lambdas & method references

A lambda is a function you can pass around like a value. This single change is why modern Java looks so different:

// Java 7 — your era: an anonymous class just to compare two strings
Comparator byName = new Comparator() {
    public int compare(Account a, Account b) {
        return a.getCustomerName().compareTo(b.getCustomerName());
    }
};

// Java 25 — one line. Account::getCustomerName is a method reference:
// "the getCustomerName method of Account" — behavior passed as data
Comparator byName = Comparator.comparing(Account::getCustomerName);

You already used one in the walkthrough: .orElseThrow(() -> new AccountNotFoundException(id)) — that () -> ... is a lambda: "a function taking nothing, producing this exception."

2 · Optional — the anti-null

null is Java's billion-dollar mistake: any reference might be null, and the compiler never warns you. Optional is a box that either contains a value or is empty — the type system now carries "might be absent" so NullPointerException stops being a lottery:

// from YOUR accounts service:
return accountRepository.findById(id)      // returns Optional
        .orElseThrow(() -> new AccountNotFoundException(id));
        // "unwrap it, and if the box is empty, throw"

Rule of thumb: methods that can fail to find something return Optional; never return null, never accept null.

3 · Records — data classes in one line

You've already read one: CreateAccountRequest. A record declares data and auto-generates the constructor, accessors, equals, hashCode, and toString. Fields are final — records are immutable by design:

public record CreateAccountRequest(
        @NotBlank String customerName,
        @Email String email,
        @PositiveOrZero Double openingBalance) { }

// plus a "compact constructor" if you need validation:
public record Money(BigDecimal amount, String currency) {
    public Money {                                   // runs before fields are set
        if (amount.signum() < 0)
            throw new IllegalArgumentException("negative amount");
    }
}
4 · Streams — assembly lines for collections

A stream describes what to do with data, not how to loop over it. Source → intermediate operations (lazy) → terminal operation (triggers work):

List activeEmails = accounts.stream()          // source
        .filter(a -> a.getStatus() == AccountStatus.ACTIVE)  // keep some
        .map(Account::getEmail)                             // transform
        .sorted()                                           // order
        .toList();                                          // collect result

You will meet streams constantly in service-layer code; read them as a pipeline, left to right.

5 · Small conveniences you'll see everywhere
// var — local type inference. Still statically typed; just less ceremony.
var account = accountService.getById(id);   // compiler knows: Account

// Text blocks — real multi-line strings (JSON, SQL):
String json = """
        {"customerName": "Priya", "openingBalance": 2500.0}
        """;

// Switch expressions — switch that returns a value:
String label = switch (status) {
    case ACTIVE -> "open";
    case FROZEN, CLOSED -> "blocked";
};
6 · Virtual threads (teaser)

Since Java 21, threads can be "virtual" — so cheap you can spawn a million of them. Traditional threads are ~1MB of OS stack each; virtual threads live on the heap and are ideal for I/O-bound work (waiting on databases, HTTP calls). In Stage 2, PayFlow's payout batch will use them to run thousands of concurrent payouts without a thread-pool tuning exercise. One line at the config level — you'll see it when we get there.
