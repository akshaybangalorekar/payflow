PayFlow · Command Reference

The daily commands

Everything we've actually used so far, one line of "why" each. Updated as we go — new tools appear here the session we meet them.

The daily loop — running PayFlow
cd ~/workspace/payflow                              # repo root first
docker compose -f docker/compose.yml up -d           # start the database, in the background
docker ps                                            # is payflow-accounts-db running? (sanity check)
cd services/accounts && mvn spring-boot:run         # boot the service; "Tomcat started on 8081" = ready
curl http://localhost:8081/api/accounts/         # hit the API
Control+C                                            # stop the service (in its terminal)
Terminal survival (macOS / zsh)
Control+Cstop whatever is running. Your universal "make it stop" key
Control+Dend-of-file: exit a program waiting for input (cat, python shell)
pwdwhere am I? (print working directory)
ls -lalist ALL files (dotfiles too) with details — your default look at a folder
cat fileprint a file to the terminal
cd ~ / cd ..go home / go up one folder
lsof -i :8081what process is holding port 8081? (find the zombie, note its PID)
kill kill that process
head / tail filefirst / last 10 lines of a file (tail -f file = follow a growing log)
Git — the daily cycle
git statusthe pre-flight check: changed? staged? clean?
git diffunstaged changes, line by line
git diff --stagedthe proposal — what the next commit will contain
git add move changes into the proposal (staging area)
git commit -m "Add ..."seal it. Imperative message, <50 chars, what+why
git pushship to GitHub (branch already tracks its upstream)
git log --oneline -5the last 5 commits — the story so far
git showthe full diff of the last commit — what a reviewer sees
git branch / git checkout -b namelist branches / create and switch to a new one
git pullfetch + merge the remote's changes down to you
Maven
mvn -versionsanity: which Maven, which Java
mvn spring-boot:runcompile and boot the app in the foreground
mvn compilequick "does it build?" — output lands in target/
mvn testcompile + run all tests (the CI gate)
mvn clean ...delete target/ first — the "turn it off and on again"
~/.m2/repositorywhere downloaded dependencies live — the basement
Docker
docker compose -f docker/compose.yml up -dstart the stack, detached (background)
docker compose -f docker/compose.yml downstop and remove the containers (data volume survives)
docker psrunning containers — with names and statuses
docker ps -aALL containers, including dead ones
docker logs payflow-accounts-dbthe database's own log (add -f to follow)
docker exec -it shopen a shell INSIDE a container
HTTP & database — curl + psql
curl urlGET request — plain, no flags needed
curl -X POST url -H "Content-Type: application/json" -d '{...}'send JSON: verb, header, body
... &run the command in the background (how we fire two curls at once; then: wait)
docker exec -it payflow-accounts-db psql -U payflow -d payflow_accounts -c "SELECT ..."run SQL directly in the database, from outside

Interactive psql too: docker exec -it payflow-accounts-db psql -U payflow -d payflow_accounts — then you're in a SQL shell (\dt lists tables, \q quits). Worth a visit: look at flyway_schema_history.

Post-it wall — the reflexes worth hard-copying
When stuckControl+C first. Terminal frozen? Ctrl+C, then Ctrl+D, then close the window.
Before every commitgit status → git add → git diff --staged → commit. Never blind-add.
Won't startPort taken? lsof -i :8081 → kill the PID. DB down? docker ps → compose up.
Truth lives inlogs (top error first), git show (last change), and the DB itself. Not in guesses.
