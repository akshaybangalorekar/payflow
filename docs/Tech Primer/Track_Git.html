Unit 2 · Undoing things safely
git restore            /* discard uncommitted changes — GONE forever */
git restore --staged   /* unstage only; changes stay in the working dir */
git commit --amend            /* edit the last commit (message or content)     */
                              /* ONLY if you haven't pushed it yet!             */
git revert               /* safe undo on shared branches: makes a NEW     */
                              /* commit that cancels the old one               */
git reset --hard         /* the grenade: rewires history, deletes work   */

The rule that keeps you out of trouble: amend private, revert public. History you've pushed belongs to the team; history you haven't is still yours to rewrite.

Unit 3 · Branches & merge conflicts

A branch is just a movable label pointing at a commit — nothing more. A conflict happens when two branches changed the same lines: git refuses to guess and hands you the file:

<<<<<<< HEAD
balance = 2500.0          /* your side */
=======
balance = BigDecimal(2500) /* the other side */
>>>>>>> feature/big-money

You edit the file to the correct union, delete the markers, git add, git commit. We will manufacture one of these on purpose in a session — so the first real one isn't traumatic.

Unit 4 · Reading diffs — the reviewer's eye

git show output is what a code reviewer reads. Anatomy: the hunk header @@ -10,7 +10,8 @@ means "old file from line 10, 7 lines; new file from line 10, 8 lines." Lines starting + were added, - removed, the rest are context. Review discipline: read every added line and ask "is this line safe, correct, and needed?" git blame answers "who wrote this line, in which commit" — archaeology, not blame.

Unit 5 · Collaboration (Stage 5)

fetch downloads the remote's history without touching yours; pull = fetch + merge. Rebase replays your commits on top of the latest remote state, keeping history linear. The golden rule: never rebase a branch anyone else has seen — rewriting shared history strands your teammates' work. Then the PR workflow: feature branch → push → pull request → review → merge. We adopt this for real in Stage 5; I stop reviewing your commits and start reviewing your PRs.
